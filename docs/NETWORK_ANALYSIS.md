## 1. 概要

ExoRust のネットワークサブシステムは設計書6.2「真のゼロコピーネットワークスタック」の理念を忠実に実装しており、
ハードウェアドライバからプロトコルスタック、アプリケーション向け非同期 API まで一貫してゼロコピーを目指しています。
Rust の安全性・所有権と `async`/`await` を活用し、VirtIO ネットワークデバイスと IOMMU をサポートします。

## 2. 不足している機能

### 2.1 プロトコル層の未実装機能

現在のスタックは基本的な IPv4/IPv6 プロトコルを含むほぼ全てのレイヤを備えているが、
運用や高度な機能のために追加実装・拡張が望まれる項目が存在する。

#### 🔴 コア拡張

| 機能 | 説明 | 優先度 | 推定工数 |
|------|------|--------|----------|
| **ルーティング機能** | カーネルレベルでの IP 転送／フォワーディングが存在しない | 高 | 中 |
| **NAT (IPv4/IPv6)** | アドレス/ポート変換機能（NAPT/ALG） | 高 | 中 |
| **QoS/トラフィッククラス** | DSCP/TOS に基づく優先制御、キュー管理 | 中 | 中 |
| **DHCPv6** | IPv6 ネットワークでの動的アドレッシング | 中 | 中 |

#### 🟠 改善・最適化

| 機能 | 説明 | 優先度 | 推定工数 |
|------|------|--------|----------|
| **TCPオプション完全実装** | Timestamp、SACK、ウィンドウスケールのネゴシエーションと処理 | 高 | 中 |
| **マルチキャストフィルタリング／VLAN** | インターフェースごとのマルチキャスト登録と VLAN メンバシップ管理 | 中 | 中 |
| **IPv6 RA/RS 拡張** | RDNSS/DNSSL オプション対応 | 低 | 小 |
| **セキュア NDP (SEND)** | 署名付き隣接発見（RFC 3971） | 低 | 大 |

#### 🟡 将来検討

| 機能 | 説明 | 優先度 | 推定工数 |
|------|------|--------|----------|
| **MPTCP/SCTP/QUIC** | マルチパス・マルチストリームトランスポート | 低 | 大 |
| **WireGuard/IKEv2** | レイヤ3 VPN | 低 | 中 |
| **SDN/OpenFlow** | プログラム可能ルーティング / フロー制御 | 低 | 中 |

### 2.2 TLS/セキュリティ層の未熟な機能

TLSモジュール（`tls.rs`）は**構造とプロトコル定義は完備**していますが、**暗号処理の実装が不完全**です。

#### 🔴 致命的

| 機能 | 現状 | 必要な対応 |
|------|------|-----------|
| **AES-GCM暗号化/復号** | プレースホルダー実装（`aes_gcm_encrypt`/`aes_gcm_decrypt`関数が参照されているが実体なし） | 暗号プリミティブの実装または外部クレート統合 |
| **ECDHE鍵交換** | パース処理のみ、実際の楕円曲線演算なし | 楕円曲線暗号ライブラリの統合 |
| **証明書検証** | `skip_verify`フラグでバイパス可能、実際の署名検証なし | X.509パースとRSA/ECDSA署名検証 |
| **PRF/HKDF** | マスターシークレット導出が未実装 | 鍵導出関数の実装 |

#### 🟠 重要

| 機能 | 現状 | 必要な対応 |
|------|------|-----------|
| **TLS 1.3完全サポート** | ハンドシェイク構造のみ | 1-RTTハンドシェイク、0-RTT再開 |
| **セッション再開** | データ構造あり、ロジックなし | セッションチケット管理 |
| **OCSP Stapling** | 未実装 | 証明書ステータス確認 |

### 3.5 ネットワーク統計・監視の改善点

#### 現状

`mod.rs` の `get_tcp_connections()` と `get_udp_sockets()` は**実装済み**:

```rust
/// Get TCP connections for netstat
pub fn get_tcp_connections() -> Option<Vec<TcpConnectionInfo>> {
    // 実際のTCB（TCP Control Block）テーブルからデータを取得
    match crate::net::endpoint::tcb_table().list_connections() {
        snapshots if snapshots.is_empty() => None,
        snapshots => Some(snapshots.into_iter().map(|snap| {
            TcpConnectionInfo {
                local_addr: format!("{}:{}", format_ipv4(snap.local.ip), snap.local.port),
                remote_addr: format!("{}:{}", format_ipv4(snap.remote.ip), snap.remote.port),
                state: format!("{:?}", snap.state),
            }
        }).collect())
    }
}
```

**✅ 実装完了**:
- 実際のTCP接続テーブルからの情報取得
- UDP ソケット一覧の取得
- `TcpConnectionSnapshot` / `UdpSocketSnapshot` 構造体

**今後の改善案**:

## 4. アーキテクチャ上の課題

### 4.1 ゼロコピーパスの完全性

現在、送信パスでゼロコピーを試みて失敗した場合のフォールバックパスが存在しますが、以下の改善が必要です：

1. **受信パスのゼロコピー一貫性**: `process_received_packet_zero_copy` は実装済みだが、全てのコードパスで使用されているか確認が必要
2. **大きなペイロードの分割**: MSSを超えるデータの効率的な分割送信

### 4.2 NUMA対応

`optimization.rs` にNUMA関連のコメントがあるが、実際のNUMA-awareなパケットバッファ配置は限定的。

### 4.3 エラーハンドリング

`PoisonLock` の使用は適切だが、エラー時のリカバリパスが統一されていない。

## 8. 結論

ExoRustのネットワークサブシステムは、**基本的なTCP/UDP/IP通信機能は実装済み**であり、ゼロコピー設計の原則に従った堅実な基盤を持っています。しかし、本番環境での使用には以下が必須です：

1. **TLS層の暗号処理実装**（セキュアな通信に必須）
2. **IPv6サポート**（現代のインターネット環境に必須）
3. **TCP接続統計・監視機能**（運用に必須）

現在の成熟度は **「開発/テスト環境向け」** であり、本番投入には上記の改善が推奨されます。
